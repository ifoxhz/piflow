# piFlow 用户使用手册

**版本**：v0.2  
**适用平台**：Windows 10 / 11（便携包）  
**更新日期**：2026-08

---

## 1. 产品简介

**piFlow** 是一款本地优先的检索增强生成（RAG）桌面应用。你可以将本机文档导入知识库，再用自然语言提问；系统会基于你的文档检索相关内容并生成回答，同时给出可点击的**来源引用**。

主对话为基于 Pi 的智能 Agent，可通过可开关的 **Skill** 查询知识库、Postgres（只读）或操作本机工作区文件。

### 1.1 核心特点

| 特点 | 说明 |
|------|------|
| 答案可追溯 | 回答附带引用与原文摘录，可定位到具体文档片段 |
| 隐私优先 | 文档、向量索引与对话数据保存在本机，默认不上传云端 |
| 目录导入 | 选择文件夹即可递归导入；后台处理，界面显示进度与预计时间 |
| 本地嵌入 | 使用本机 BGE-M3 模型做向量化（首次导入会占用一定时间与 CPU） |
| 可选远端生成 | 可在设置中配置局域网 / 远端 Ollama；未配置时仍可基于检索给出摘要 |
| piFlow Agent | 侧栏独立入口；Postgres 只读查询与本地文件 Skill 可分开启用 |

### 1.2 本手册覆盖范围

- Windows **便携包**的安装、启动与日常使用  
- 知识库导入、RAG 对话、**piFlow**、设置、常见问题  

> **说明**：开发者编译、WSL 调试等内容请参阅 `docs/development-windows.md`。piFlow 技术设计见 `docs/piflow.md`。

## 2. 系统要求

| 项目 | 建议配置 |
|------|----------|
| 操作系统 | Windows 10 / 11（64 位） |
| 内存 | 建议 **16 GB** 及以上 |
| 磁盘 | 至少 **10 GB** 可用空间（含嵌入模型与首次解压） |
| 运行时 | 需已安装 **WebView2**（Win10/11 通常已预装） |
| 网络（可选） | 若使用远端 Ollama，需能访问对应主机与端口（默认 `11434`） |
| piFlow Local FS（可选） | 使用 `bash` 工具时需安装 **Git for Windows**（提供 `bash.exe`） |
| piFlow Postgres（可选） | 可访问的 PostgreSQL 实例 |

便携包已内置：

- 桌面程序（`piFlow.exe`）  
- Node 运行时与 RAG 后端（首次启动自动解压）  
- 嵌入模型 **BGE-M3**  

首版便携包**默认不包含**：本地大模型 GGUF、OCR 扫描版 PDF 增强（扫描件效果可能较差）。

## 3. 安装与启动

### 3.1 获取与解压

1. 获得压缩包，例如：`RAG-Assistant-0.1.0-portable.zip`  
2. 解压到较短路径，例如：`D:\apps\RAG-Assistant`  
   - 避免过深路径或仅含中文/特殊符号的路径，以减少首次解压失败概率  
3. 进入解压目录，确认至少包含：

| 文件 / 目录 | 作用 |
|-------------|------|
| `piFlow.exe` | 主程序 |
| `runtime\` | 内置 Node 运行时 |
| `models\` | 嵌入模型等 |
| `rag-server.zip` | RAG 后端包（首次启动解压） |
| `README.txt` | 简要说明 |

### 3.2 首次启动

1. 双击 **`piFlow.exe`**  
2. 首次启动会自动将后端解压到：  
   `%APPDATA%\piFlow\sidecar\`  
3. 等待窗口打开；后端默认监听本机端口 **`3847`**  
4. 若杀毒软件拦截，请将安装目录与上述 AppData 目录加入白名单后重试  

### 3.3 日常启动

之后直接运行 `piFlow.exe` 即可；一般无需再手动启动其他服务。

### 3.4 数据存放位置

| 内容 | 大致位置 |
|------|----------|
| 用户数据 / 数据库 / 日志 | `%APPDATA%\piFlow\` |
| 后端解压目录 | `%APPDATA%\piFlow\sidecar\` |
| 开发态数据目录 | 仓库内 `.data\`（含 `bluelamp.db`、Ollama / Postgres / piFlow 配置） |

卸载或清理时：退出程序后删除便携文件夹；如需彻底清除数据，再删除上述 AppData 目录。

## 4. 界面概览

主窗口大致分为：

| 区域 | 功能 |
|------|------|
| **piFlow（主对话）** | Pi Agent：知识库检索（kb tools）+ Postgres 只读 + 可选本地文件；会话与 Sources 引用 |
| **Knowledge Base（知识库）** | 导入文件夹、查看已索引文档、导入进度与活动日志（不承担主问答） |
| **Settings（设置）** | 模型（Ollama/DeepSeek）、Postgres、Local FS / Knowledge Skill、服务状态等 |

侧边栏 **New Chat** 新建 **piFlow** 会话；会话列表为 piFlow 历史。导入文档后，piFlow 的 Knowledge skill 状态会更新为「已就绪」。

## 5. 配置生成服务（Settings → Ollama）

piFlow 在本机完成向量检索；对话生成推荐连接 **Ollama** 或 Settings 中的 **DeepSeek**（互斥）。导入仍使用本机 BGE-M3。

### 5.1 配置步骤

1. 打开 **Settings**  
2. 填写 **Ollama URL**，例如：`http://10.0.0.7:11434`  
3. 填写 **模型名**，例如：`qwen3.5:4b`（需与 Ollama 中已拉取的模型一致）  
4. 可选填写 **中文模型**  
5. 点击 **确定 / 保存**（配置立即生效）  
6. 查看连通状态；若显示不可达，请检查网络与防火墙后再试  

### 5.2 未配置 Ollama 时

- **RAG**：仍可导入文档并提问，可能返回检索摘要与引用，而非完整生成回答。  
- **piFlow**：需要 Ollama；未配置时无法发起 Agent 对话。

### 5.3 Ollama 侧准备（管理员 / 运维）

在 Ollama 所在机器上：

```text
ollama pull <你的模型名>
```

并确认 Windows 客户端能访问：`http://<主机>:11434/api/tags`。

## 6. 导入知识库

### 6.1 支持的文件类型

| 类型 | 扩展名 |
|------|--------|
| PDF | `.pdf`（文本层 PDF 效果最佳） |
| Markdown | `.md` / `.markdown` |
| 纯文本 | `.txt` |
| HTML | `.html` / `.htm` |

> 扫描版 / 纯图片 PDF：首版便携包默认关闭 OCR，识别效果可能不佳。请优先使用可选中文字的 PDF。

### 6.2 导入步骤

1. 打开 **Knowledge Base**  
2. 点击 **Import folder**（导入文件夹）  
3. 在系统对话框中选择包含文档的目录（会递归处理子目录）  
4. 确认后开始后台导入  

### 6.3 进度说明

导入过程中你可能看到：

| 信息 | 含义 |
|------|------|
| 当前文件名 | 正在处理的文件 |
| 预计时间（ETA） | 根据页数 / 块数估算的剩余时间 |
| `N / M pages` | PDF 按页窗口进度（默认每窗约 20 页：解析→切块→向量化） |
| `N / M chunks` | 向量化进度（文本块）；指纹未变的页会显示「复用」而不重算向量 |

说明：

- **解析**通常较快；大部分时间花在本机 **BGE-M3 嵌入**（CPU 上约每块数秒量级，大文档会明显更久）。  
- 进度会持续更新；请耐心等待，勿重复多次点击导入同一目录。  
- 未变更的文件可能被自动**跳过**。  
- 首版同一时间通常只运行 **一个** 导入任务。

### 6.4 导入完成后

- 文档列表中会出现已索引文件  
- 底部活动日志会显示成功 / 跳过 / 失败汇总  
- 失败项请检查文件是否损坏、是否受权限限制，或是否为不支持的格式  

### 6.5 体积与时间参考（经验值）

| 文档规模 | 粗略预期 |
|----------|----------|
| 数页～十几页 PDF | 约 1～数分钟 |
| 百页级文字 PDF（约百余 chunks） | 约数分钟～十余分钟（视 CPU 而定） |
| 数百页大书 | 可能数十分钟，请关注 chunk 进度与 ETA |

## 7. 对话提问（Chat · RAG）

### 7.1 基本用法

1. 确保已至少成功导入部分文档  
2. 打开 **Chat**（或侧栏 New Chat）  
3. 在输入框输入问题，例如：  
   - 「这份白皮书的主要结论是什么？」  
   - 「文档里提到了哪些人名？」  
   - 「某某功能在哪一节说明？」  
4. 发送后等待回答  

首次提问或长时间空闲后，嵌入模型可能有短暂**冷启动**，首条可能稍慢。

### 7.2 「规划」开关（查询方法）

输入框旁有 **规划** 按钮，用于选择本条（及之后）提问的检索方式。按钮高亮表示已开启。设置会记在本机，下次启动仍保留。

| | **规划开**（推荐默认） | **规划关** |
|--|------------------------|------------|
| 流程 | 识别问题意图 → **LLM 生成检索计划**（可拆成多条查询、关键词等）→ 多路向量检索 → LLM 生成回答 | **用户原句**直接做向量检索 → LLM 生成回答 |
| 界面提示 | 「LLM 构建检索结构 → 向量搜索 → LLM」 | 「原句 → 向量搜索 → LLM」 |
| 速度与资源 | 多一次规划用的 LLM 调用，通常更慢，更依赖 Ollama | 更快、更省；Ollama 仅用于最终生成（若已配置） |
| 适合场景 | 复杂问题、列举实体、多条件、需要改写/拆查询 | 简单直问、对比两种检索效果、Ollama 较慢或不稳时 |

补充说明：

- **规划开**时，规划阶段与回答生成都会调用 Ollama（若已配置）。Ollama 不可达时，规划可能退化或失败，可临时关掉规划再试。  
- **规划关**不等于关闭 AI 回答：仍会检索知识库；有 Ollama 时仍会生成完整答复，只是跳过「先写检索计划」这一步。  
- 若感觉答非所问，可切换开关各问一次，对比引用是否更贴题。  

### 7.3 引用与溯源

回答下方或侧栏通常会显示**引用（Citations）**：

- 来源文档名称  
- 相关段落摘录  
- 可据此核对原文，降低「幻觉」风险  

若引用为空或很少：可能是问题与知识库无关，或文档尚未导入完成 / 文本层过少。

### 7.4 多轮对话

同一会话中可继续追问；系统会尽量利用会话上下文（如指代「上面提到的人」）。重要新主题建议 **新建会话**，以免上下文干扰。

### 7.5 会话管理

- **新建**：开始新话题  
- **切换**：在侧边栏选择历史会话  
- **重命名 / 删除**：便于整理

## 8. piFlow（工作流 Agent）

piFlow 与知识库 Chat **分开**：它不检索你导入的文档，而是按已启用的 **Skill** 调用工具（查库、读写本地文件等）。

### 8.1 打开 piFlow

1. 点击侧栏底部 **piFlow**  
2. 左侧可见 skill 状态列表与会话列表  
3. 右侧输入自然语言问题并发送  

页面上会显示当前 Skill（例如 Postgres 只读、本地文件）是否启用 / 就绪。配置入口在 **Settings**。

### 8.2 Skill：Postgres 只读

用于用自然语言查询 PostgreSQL（**只读**，禁止 DELETE / DROP 等）。

**配置：**

1. 打开 **Settings → Postgres（piFlow skill）**  
2. 勾选 **启用 Postgres 只读 skill**  
3. 填写 Host / Port / Database / User / Password（可选 SSL）  
4. 可先点 **测试连接**，再点 **保存连接**（保存时会预热 schema 缓存）  

**示例问题：**

- 「最后一个患者是谁，列出他的资料」  
- 「患者 ID 145 有多少个 study？」  

**说明：**

- 连接信息保存在本机（开发态为 `.data/postgres-config.json`）  
- Agent 只会执行只读 SQL；破坏性语句会被拦截  
- 需要 Ollama 已配置且可达  

### 8.3 Skill：Local FS（本地文件）

用于在指定**工作区目录**内读文件、用 bash 辅助、按需写文件。与 Postgres Skill **分开开关**。

**配置：**

1. 打开 **Settings → Local FS（piFlow skill）**  
2. 勾选 **启用本地文件 skill**  
3. 填写工作区**绝对路径**（必须是已存在的文件夹），例如：`D:\dev\my-project`  
4. 可选：是否 **允许写入**（关闭则仅 `read` / `bash`）  
5. 点击 **保存 Local FS / skill 开关**  

**Windows 注意：**

- 使用 `bash` 前请安装 [Git for Windows](https://git-scm.com/download/win)，否则 bash 工具会失败  
- 请勿把工作区设成整个系统盘；只指向你允许 Agent 接触的项目目录  
- 即使允许写入，**删除文件 / 破坏性清理**仍被 no-delete 策略禁止  

**示例问题：**

- 「列出工作区根目录有哪些文件」  
- 「打开 README.md 并总结」  
- 「在 docs 下新建一个 draft.md，写上今日纪要」（需开启允许写入）  

### 8.4 piFlow 会话

- 点击 **新对话** 开始新会话  
- 会话保存在服务端数据库（与 RAG 侧边栏会话分离）  
- 对话中可能出现 `tool → pg_query` / `tool → read` 等提示，表示 Agent 正在调用工具  
- 请等待完整回答；若长时间无结果，检查 Ollama、Skill 配置与（Local FS）Git Bash  

### 8.5 安全提示

| 项 | 说明 |
|----|------|
| 无删除 | `no-delete-data` 始终生效：不删库、不删文件 |
| Postgres | 仅只读 SQL |
| Local FS | 限制在你配置的工作区内；写操作可单独关闭 |
| Ollama | 提示词与工具结果会发往你配置的 Ollama 主机 |

## 9. 使用建议与最佳实践

1. **先导入、再提问（RAG）**：导入完成后再做正式问答。  
2. **目录整理**：将同一主题文档放在同一文件夹，减少无关噪声。  
3. **优先文本 PDF**：可复制文字的 PDF 远优于纯扫描件。  
4. **问题尽量具体**：带上文档名、术语、时间范围，检索更准。  
5. **善用「规划」**：复杂问法保持开启；要快测或排查检索问题时可暂时关闭。  
6. **核对引用**：重要结论请点开引用对照原文。  
7. **Ollama 放近一点**：局域网内低延迟 GPU 机器通常体验更好。  
8. **piFlow 分 Skill 使用**：只查库时保持 Local FS 关闭，减少模型误调 bash。  
9. **Local FS 工作区收窄**：只授权必要项目目录，并按需关闭写入。

## 10. 隐私与安全

- 文档内容与向量默认保存在**本机** SQLite / 本地目录。  
- 配置远端 Ollama 时，**检索到的相关片段、piFlow 提示词与工具结果**会发往该 Ollama 服务；请仅连接你信任的服务器。  
- Postgres 密码保存在本机配置文件中，请妥善保护用户数据目录。  
- 请勿将便携目录与 AppData 中的数据库随意拷贝到不可信环境。

## 11. 常见问题（FAQ）

| 现象 | 可能原因与处理 |
|------|----------------|
| 双击无反应 / 闪退 | 检查 WebView2；杀毒拦截；换短路径解压；查看 AppData 下日志 |
| 窗口打开但导入/聊天失败 | 后端未就绪或端口 `3847` 被占用；退出后重开，或结束占用该端口的进程 |
| Ollama「暂不可达」 | 检查 URL、模型名、防火墙与远端服务；配置仍可保存，修好后再聊 |
| 导入很久进度不动 | 大文件嵌入本身较慢；关注 `N / M chunks`；若进程崩溃再重试 |
| 扫描 PDF 几乎无内容 | 首版便携默认弱 OCR；请换文本层 PDF 或后续开启 OCR 版本 |
| 回答很空或只有摘要 | 未配置 / 未连通 Ollama；配好后再问 |
| 换电脑后知识库没了 | 数据在原机器 AppData；需迁移该目录或重新导入 |
| 端口被占用 | 其他 piFlow / 开发态服务占用了 `3847`；只保留一个实例 |
| piFlow 半截无响应 | 确认 Ollama 正常；Postgres/Local FS 是否就绪；Local FS 是否缺 Git Bash；可新开对话重试 |
| piFlow bash 报错 | Windows 未装 Git Bash，或工作区路径无效 |
| Postgres 工具提示未配置 | Settings 中保存连接，并确认「启用 Postgres 只读 skill」已勾选 |
| Settings 底部看不见 | 在设置页内向下滚动；内容较长时主区域可滚动 |
